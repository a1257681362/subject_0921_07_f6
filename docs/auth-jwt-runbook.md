# 无状态登录（JWT 双令牌）上线 Runbook 与操作指引（F6）

本系统登录改为**无状态令牌**：登录后服务发两张"通行证"，不再依赖服务器保存登录状态。
本文分两部分：**第一部分是给机手看的操作指引（可直接打印贴工位旁）**，
第二部分是给值班/运维的上线与应急手册。

---

# 第一部分：机手操作指引（贴工位旁）

## 一、登录

1. 打开系统，在登录页输入**工号（用户名）和密码**，点"登录"。
2. 登录成功后会自动拿到两张通行证，系统自己保管，**不用记、不用抄**：
   - **通行令牌（访问令牌）**：有效期 **30 分钟**。每次操作系统自动带上，不用管。
3. 一直正常使用时，系统会在后台**自动续期**，不会做到一半被踢出。

## 二、什么情况下要重新登录

- 页面放着**超过 30 分钟没动**，再操作时提示"登录已过期"→ 重新输一次密码即可，**之前录的数据不丢**。
- 如果系统提示"登录已全部失效，请重新登录"→ 说明同一个账号的通行证在别处又刷过一次
  （可能是换手机/换电脑登录，或通行证被别人拿去用了）。**重新登录即可**；若不是本人操作，
  请立即联系管理员并修改密码。

## 三、下班 / 换人手

- 点页面右上角**"退出登录"**。退出后旧通行证立即作废，别人拿不到。
- 换人操作请先退出，再用自己的工号登录。**不要把账号密码给别人代操作**——每条记录都会记操作人工号。

## 四、改密码

- 首次拿到账号（默认密码见管理员发放的小条）登录后，请到"个人中心 → 修改密码"改成自己的密码。
- 新密码 **8 位以上**。改完密码后，本机和其他设备上的旧登录会**全部退出**，需用新密码重新登录。
- 忘记密码：找管理员重置，自己无法绕过。

## 五、常见提示对照

| 屏幕提示 | 含义 | 怎么办 |
| --- | --- | --- |
| 未登录或登录已过期，请重新登录 | 令牌缺失/过期 | 重新登录 |
| 登录已失效，请重新登录 | 已退出，或登录因安全原因被作废 | 重新登录；非本人操作请改密码并报管理员 |
| 刷新令牌已被使用……该登录已全部失效 | 同一登录被重复续期（疑似通行证泄露） | 重新登录；必要时改密码 |
| 用户名或密码不正确 | 账号或密码错（系统不区分是哪个错） | 核对后重试；连续不对找管理员 |
| 账号已停用，请联系管理员 | 账号被停用 | 联系管理员 |

> 给机手的话：**正常用什么都不用懂**——登录、干活、退出；过期了就再登一次。

# 第二部分：上线与运维 Runbook

## 机制速览

- **双令牌**：访问令牌（HS256 JWT，默认 30 分钟）走 `Authorization: Bearer <token>`；
  刷新令牌（默认 7 天）只对 `POST /api/auth/refresh` 使用。
- **无状态**：Shiro 过滤链只校验令牌，不建 HttpSession、不发任何 Cookie（含 rememberMe）；
  服务端唯一状态锚点是 `t_refresh_token` 刷新令牌台账。
- **刷新即轮换（一次性）**：旧刷新令牌 `ACTIVE→ROTATED` 指向新令牌，旧令牌立即失效；
  台账 CAS + 令牌 jti 唯一约束保证并发刷新只有一笔成功。
- **重放连坐**：已 ROTATED/REVOKED 的刷新令牌再次出现，判重放，**同会话整条吊销**
  （当前 ACTIVE 刷新令牌置 REVOKED + 会话级标记，让仍有效的访问令牌也立即 401）。
- **登出走黑名单**：访问令牌按 jti 入 `t_token_blacklist`，保留到令牌自身 exp 再加一个时钟偏移容忍窗口（默认 +61 秒，杜绝容忍窗口内的缝隙）。
- **到期自动清理**：Quartz 每日 03:30 物理删除过期黑名单行与过期刷新令牌台账行
  （黑名单按 `expire_time`、刷新台账按 `expires_at` 并留 61 秒时钟偏移缓冲；`auth.jwt.cleanup-cron` 可调）。
- **令牌无敏感明文**：载荷仅 `iss/uid/sid/jti/typ/iat/nbf/exp`，没有用户名、姓名；
  `/api/auth/me` 等信息由服务端按 uid 现查。
- **口令存储**：每用户 16 字节随机盐 + SHA-256 迭代 1024 轮；库内无明文。

新增表：`t_sys_user`、`t_refresh_token`、`t_token_blacklist`（schema 版本 `f6-auth-stateless`）。

## 第一步：备份（不备份不变更）

```bash
scripts/backup-evops-data.sh pre-f6-auth
```

检查点：备份目录内 `.mv.db`、`schema.sql.bak`、`application.yml.bak`、`MANIFEST.sha256` 齐全，
`sha256sum -c MANIFEST.sha256` 全部 OK。备份前确认应用已停止。

## 第二步：变更

1. **配置签名密钥（必做）**。生成一个固定密钥并通过环境变量注入，不要写进配置文件提交：

   ```bash
   openssl rand -base64 32        # 输出形如 k9X...= 的 44 字符
   export AUTH_JWT_SECRET='<上一步输出>'
   ```

   - 不配密钥时系统每次启动随机生成：能跑，但**重启即全员掉线**，仅限本机开发。
   - 密钥 < 32 字节（解码后）系统拒绝启动。
   - 轮换密钥：换新值重启即可，旧令牌验签失败→全员重新登录（可接受的停机式轮换）。
2. 部署新代码并启动。`schema.sql` 幂等：三表不存在才建；
   首次启动写入引导账号 **admin / admin123**（仅当不存在时插入，改密后重启不会被覆盖）。
3. 配置项（`auth.jwt.*`，均有默认值）：

   | 配置 | 默认 | 说明 |
   | --- | --- | --- |
   | `secret` | 空（随机） | Base64 HS256 密钥，生产必填，建议环境变量注入 |
   | `access-token-ttl-minutes` | 30 | 访问令牌有效期 |
   | `refresh-token-ttl-days` | 7 | 刷新令牌有效期（每次刷新顺延一个完整周期） |
   | `filter-enabled` | true | 鉴权过滤链总开关，**生产必须 true** |
   | `scheduling-enabled` | true | 每日清理调度开关 |
   | `cleanup-cron` | `0 30 3 * * ?` | 清理时刻（避开 02:10 勾稽作业） |

检查点：

- [ ] 启动日志无建表/SQL 异常；未配置密钥时应有 WARN `auth.jwt.secret 未配置`
- [ ] `curl localhost:8080/api/health` 正常；无令牌访问业务接口返回 **401**
- [ ] 响应头无任何 `Set-Cookie`
- [ ] 存量功能 `mvn test` 全绿

## 第三步：上线后立即做的两件事

1. **改掉默认口令**：用 admin/admin123 登录，`POST /api/auth/change-password`
   （或个人中心页面）改成强密码；改密即吊销全部旧会话。
2. 按机手花名册创建账号（当前由管理员直接维护 `t_sys_user`，口令哈希用
   `PasswordHasher` 同口径写入：随机盐 + 1024 轮 SHA-256）。

## 验证清单（可重复执行）

1. 无令牌 `GET /api/machines` → **401**。
2. `POST /api/auth/login`（admin/新密码）→ 拿到 accessToken/refreshToken；
   解码访问令牌载荷，只有 uid/sid/jti/typ/时间戳，**无用户名**。
3. 带令牌访问业务接口 → 200；响应**无 Set-Cookie**；新建一条业务数据，
   审计列 `create_by` = 登录用户 ID（不再是 0）。
4. `POST /api/auth/refresh` 用旧刷新令牌 → 新双令牌；**再用一次旧的** →
   `success=false` 且提示"已全部失效"；随后用刚轮换出的新访问令牌访问 → **401（连坐）**。
5. `POST /api/auth/logout`（带访问令牌，可带 refreshToken）→ 再用该访问令牌 → **401**。
6. 篡改签名末字符 / alg=none / 刷新令牌调业务接口 / 访问令牌调刷新 → 全部拒绝。
7. 改密后旧访问、旧刷新令牌均立即失效；旧密码登录失败、新密码成功。
8. 清理：`t_token_blacklist` 与 `t_refresh_token` 中手工造一条过期行，
   等 03:30 调度（或直接调用 `AuthTokenCleanupScheduler.runCleanup`）→ 过期行被物理删除、
   未过期行保留。

## 应急

- **鉴权组件异常导致全员无法工作**：可临时设 `auth.jwt.filter-enabled=false` 重启，
  接口全部放行（等同于旧行为）。**这是降级开关不是常态**：排障后必须立即恢复 true，
  期间业务操作审计人回落 system(0)。
- **怀疑密钥/账号泄露**：换新 `AUTH_JWT_SECRET` 重启（旧令牌全废）+ 重置相关账号密码。
- **单个账号异常**：`t_sys_user.status` 置 `DISABLED`，该用户新请求即被 JwtRealm 拒绝；
  在途令牌最长 30 分钟自然过期，或按 uid 把其 ACTIVE 刷新令牌置 REVOKED(PASSWORD_CHANGE) 立即连坐。

## 回滚

- 回滚代码后过滤链恢复旧的全放行口径；新表保留不影响旧版本运行（旧版本不读写）。
- 已发出的 JWT 在旧版本下不校验，无需清理；`t_token_blacklist`/`t_refresh_token` 可保留备查。
